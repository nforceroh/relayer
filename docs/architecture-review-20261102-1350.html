Problem: the config module exists but three env fallback paths survive — main.py still reads LOG_LEVEL/SECRET_KEY/UI_PROTOTYPE directly, and both factories keep a settings-less branch that re-reads env. The interface says "settings in", but callers can still bypass it.

Solution: delete the fallback branches — factories require settings; main.py takes secret_key, ui_prototype, and log level from them. Env reads collapse to one module.

  • locality: every env read in one module
  • deletion test passes: fallbacks are pass-throughs
  • interface stops lying about bypass routes

2 · Extract the shared stylesheet

Worth exploring in-process

app/templates/index.html (443 CSS lines) · app/templates/prototype.html (80)

Before — sidebar CSS lives in index.html

index.html: 443-line style block (sidebar + controls + theme)

After — one stylesheet, two thin templates

static/relayer.css

sidebar · recipient controls · theme switch — served once, cached

templates link it; prototype keeps its 80-line switcher block

Problem: the sidebar stylesheet lives inside index.html, so every page load re-sends 443 lines of CSS and the prototype template can't share it without duplication.

Solution: move the shared style block to static/relayer.css and link it from both templates; the prototype keeps only its switcher-specific rules.

  • locality: styling rules in one file
  • browser caches it; pages get smaller
  • prototype deletion leaves CSS intact

After — app factory takes settings

Problem: tests need an import-order bootstrap (_bootstrap before app.main) because the app reads env at import; the discover -s tests pitfall already bit once.

Solution: an app factory — create_app(settings, store) — so tests construct the app with explicit inputs and the bootstrap disappears.

  • tests accept dependencies, not env
  • bootstrap module deleted
  • two adapters already justify the seam
Cost note: touches every route's module-level references (INGEST_TOKEN, ADMIN_*, store); the largest diff of the three.
