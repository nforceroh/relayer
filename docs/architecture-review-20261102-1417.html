Problem: the forward pipeline's tests cover the happy path and error statuses, but the two functions that handle real-world mail messiness — multipart walking with silent except: pass, and the HTML-to-text fallback — have zero coverage. These are where malformed emails will bite.

Solution: add composition tests for _extract_parts (multipart with both parts, html-only, plain-only, unparseable part content) and _html_to_text (tags, entities, whitespace). No production change — the pure functions are already the seam.

  • locality: malformed-mail bugs become testable
  • leverage: existing interface, new coverage
  • zero production risk

3 · Extract the adapter's connection boilerplate

Speculative in-process

app/db.py (88 lines, 5 identical try/finally blocks)

Before — 5× the same open/close dance

conn = self._connection() / try / with cursor / finally close
…repeated 5 times…

After — one context helper

@contextmanager _cursor()

each method: with self._cursor() as cur: cur.execute(...)

~30 lines deleted; the SQL stays front and center

Problem: five methods repeat the identical connection/try/finally boilerplate; the SQL — the only part that differs — is buried inside it.

Solution: a @contextmanager helper owning the connection lifecycle; each method keeps only its query.

  • locality: connection handling in one place
  • SQL becomes the visible content
  • ~30 lines deleted
Honest caveat: the adapter is stable and thin; this is polish. Worth bundling with the next db change rather than as its own commit.
